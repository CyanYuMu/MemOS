# 治理、演进与 P5 交付实施合同

日期：2026-11-09；数据面基线 `c4c65b73`，分支 `codex/skill-prototype-lifecycle`，控制面/前端分别使用同名前缀加 `-be` / `-fe`。本合同先于实现与新运行提交，详细子协议先于对应实现冻结。

## 1 用户授权与事实边界

用户本轮要求助手处理裁决、必要路径与历史挑战、无依据规则修订、失效传播、恢复撤回、新版验证发布，并在自行测试后执行 P5。该授权允许本轮代办具体审阅及发布，无需重复请求同一授权。每次管理决定必须写明“用户授权、助手受托审阅/执行”、具体证据和理由；不能宣称用户逐条亲审，也不能把自动谓词通过冒充人工语义判断。现有账户权限和事务门槛保留。

原 P4 实验、旧 unknown、C1/C2 批次及已有裁决不可改写。现有 C2 v2 包先再次核对版本、水位、序号和实际证据，仅据其支持范围登记两个验证分支；不补造 confirm/repair 时序。旧 P3 无完整工件记录明确保留“证据不足”，不以复跑替换缺失历史。

发布范围以实际支持的语义为准：不为凑齐原 22 分支反复试跑。先复核真实 Memory 来源，再形成范围明确的新候选；保留三类停止边界，健康无修改、有限修复失败和工具不可用需要各自可表达的受信事实。缩范围是新的不可变版本，不能只删验收项、复用旧版覆盖或标注新的独立来源数量。

## 2 工作包与先后关系

| 工作包 | 范围 | 验收 |
| --- | --- | --- |
| D1 证据收尾 | C2 受托裁决、旧 P3 证据不足、来源语义审阅及规则范围决定 | 原始记录保留；每项有独立理由与证据，不授予缺失分支 |
| D2 生命周期 | 来源/工具观察、挑战处置、依赖传播、恢复/撤回及准入 | 实际 Memory/工具探针与 Neo4j；多根因、循环/缺失/跨项目、相关边不传播、并发发布拒绝 |
| D3 新版资格 | 来源绑定修订；预登记健康/修复/范围外/缺证据/未解决/工具故障任务，独立隔离与真实 Claude | 固定身份和预算；全部拟发布规则/边界证据；受托语义审阅；独立固定包发布 |
| D4 P5 | 正常使用→变化→阻断/依赖传播→恢复或新版→发布→再次加载→反馈 | 真实服务操作、浏览器展示、所有成功失败和旧版本可回读，操作及验收文档完整 |

D2 与 D3 的独立模块可并行开发；D3 的真实批次必须另行先冻结完整候选、任务、预算、协议和运行上限。D4 只有在对应实际资格满足后执行，不使用 management_test 记录冒充真实发布。

## 3 生命周期合同

新增独立 `skill_lifecycle` 包。观察、影响和决定为追加记录；只更新状态投影。来源比较实际回读的受作用域约束内容/元数据语义摘要；区分 changed、unavailable、invalid 和 restored。工具指纹绑定 CLI 文件与版本、工具名称、参数/返回约定及受信探针。不能只比较版本号。

每个根因绑定受影响的固定版本、预期/实测摘要、检测器版本、前一观察及证据摘要。相同观察幂等，失效恢复观察不自动恢复发布。`REQUIRES` 按固定版本反向传递，保留全部根因与路径；`RELATED_TO` 不传播；`SUPERSEDES` 仅记录替代，不能自动重绑定依赖。缺版本、循环、跨项目或未发布依赖拒绝准入。

发布包绑定生命周期水位、精确依赖 release IDs 和现有来源/验证/裁决；发布在项目事务内再次核验。所有新评测、审阅准备、发布、normal 加载及任务结束均检查来源和工具；检查失败拒绝新加载。运行中的固定上下文不能被远程擦除，结束时记录准入变化。恢复需当前观察、重新验证依据及受托审阅包；撤回不能自动复活，新版发布不批准旧版本。

挑战处置必须引用当前固定包和证据摘要，追加处置原因；旧挑战正文、历史运行结果和缺失工件事实保留。来源语义不足可以通过新范围版本处置，不允许无条件把旧候选所有挑战变为“通过”。

## 4 接口、权限与兼容

Python 私有 API 经 Go 同源认证提供 `impact_scan`、`impact_prepare`、`impact_review`、`challenge_resolve` 等明确命令；正文不可指定 actor、任意宿主路径/命令或自报观测通过。角色来自已有会话，管理写要求 manage。写入必须绑定 expectedSequence、operationId 和 reason，包审阅还绑定 packageId/packageHash。扫描只调用服务端已注册检查器。详细 JSON 与枚举在生命周期子合同冻结，再实现跨组件。

新增事实使用显式 schema 6（或单独版本合同），不回退为旧 schema 1–5。健康成功与修复成功分别计数，停止不增加修复率。旧 adapter、branch_*、collector 及锁已被真实摘要绑定，不修改或向旧 adapter 目录新增文件；新执行器放独立包。管理层的增量分派必须通过旧实际回读验证。

新增类别写图前停止本次旧管理服务并启动识别新合同的版本；Memory、Neo4j、Qdrant 不随意停机。服务日志保留在终端，前端在浏览器展示。私有配置、原生工件、运行轨迹和模型凭据不进入 Git。

## 5 测试和最终交付

按 TDD 补真实缺陷与边界测试，再实现；使用已有 `.venv`、Go 与 pnpm 环境，不安装/升级依赖。Python 限定 Ruff 与相关回归，Neo4j 使用隔离测试项目；Go `make check`，前端 `pnpm verify`，再做实际来源/工具探针、独立 Claude 验证、发布及 P5 操作。

最终报告分开列出自动测试、真实任务、受托审阅、发布、演进与反馈；明确费用、失败和限制，不能把小样本合格称为总体效果提升。交付开发合同、操作步骤、故障恢复说明、固定证据索引与验收结果。每个增量使用中文 commit，明确暂存路径；不推送、合并或改写旧 Git 历史。
