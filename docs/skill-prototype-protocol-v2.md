# 新执行协议：声明门禁与真实错误送达

日期：2026-11-09。接续 [真实批次结果](skill-prototype-delivery-record.md)。本文件先于新实现冻结 G0；G1 以后的任务、导出和真实批次细节须另行补齐后执行。目标仍是完成新候选资格、发布与 P5，不把本轮自动测试或失败批次称为交付完成。

## 1 问题与不可变边界

真实首批证明提示词不足以保证动作声明早于编辑；当前请求和附带健康检查也容易被混淆。另有真实 MCP 错误使用 JSON 字符串，旧消费者只接受成功 text blocks，错误送达与停止行为因而被混为捕获缺失。

`skill_release`、schema 6、全部七单元和六任务资格资产保持原字节。私有冻结清单登记 23 个生产文件、520 个批次文件、1130 个资格文件；旧 C2 的冻结另行保留。不得向 `skill_adapter` 或 `skill_release` 增加文件，不 monkeypatch 旧模块全局变量。新增实现放 `skill_release_v2`，未来 assessment 为显式 schema 7；管理分派增量接入，旧记录仍走旧合同。

新候选需要新的不可变 revision。当前 Dream 示例只能支撑观察到的参数绑定修复，不支持任意 mock、fixture 或反馈修复。适用条件必须先核对当前请求，再判断相应合同及现有行为；附带 Dream 健康不能替代 scoped 请求或未知新策略。公开观察只说明收到的事实，推断须标明，不能虚构具体异常文本或已执行轮数。

## 3 G0 门禁合同

门禁只检查过程和引用，不替 Agent 判断自然语言范围或选择分支。输入为固定 run/attempt、当前 session、候选规则图、允许编辑路径、公开请求文档及当前快照；不包含隐藏任务预期、参考补丁或隐藏检查。

宿主使用单个受锁保护的状态机和追加审计日志。Read 与初始公开检查始终可执行。只有当前成功的原生工具返回可以登记已读文档/已送达公开检查；Agent 自报引用不能造出观察。

Agent 通过新声明传输显式提交 `{rule_id, phase, branch_index, observation, decision, evidence_refs}`。phase 为 select / act / check / exit；branch_index 为固定规则的分支索引或 null。入口 select 必须引用当前请求和当前检查；非退出目标先显式 select 进入，再声明 act，不能靠编辑后的 check 补足之前的选择。目标规则 select 可用 null 表示进入该规则，最终分支在实际结果出来后选择。健康与停止不要求编辑，也不要求虚构 act。

声明有 pending 与 committed 两阶段：MCP 收到参数仅形成宿主回执，原生 PostToolUse 确认同一次声明工具的返回后才 committed。PreToolUse 为声明工具登记原生 tool_use_id 和规范化输入摘要；MCP 只能匹配唯一待处理请求，不能信任 Agent 自报 tool_use_id。并行提交声明和编辑时，尚未确认的声明不能放行编辑。歧义、缺少回执或身份不符拒绝。

Edit/Write 的 PreToolUse 必须取得宿主许可，绑定 run/attempt/session/tool_use_id、工具名称与输入摘要、路径、编辑前快照、已提交入口/目标/动作声明及公开证据。许可只消费一次，重复 tool_use_id、重放、旧快照、不同输入、越界路径、符号链接、已退出或观察失效均拒绝。同时只允许一项待完成编辑，避免并行检查和修改产生竞态；完成回调核对实际前后状态后释放。

审计严格区分 attempted、denied、permitted、executed、failed。拒绝的编辑不是实际补丁；原生阻断有完整证据时不记成 capture_incomplete。所有拒绝和纠正永久保留，是否满足资格由后续固定评分协议决定，不能在捕获层静默抹去。任何 Hook 失败、超时、失联或无合法输出都不能放行写操作。

宿主不能伪造声明、改写 phase、自动选择正确 branch，也不能把动作文字当成事实已发生。自然语言条件、动作语义、错误归因以及合理停止继续由独立检查和语义审阅决定。

## 4 G0 错误返回合同

正常 text blocks 与 `is_error:true` 的 JSON 字符串是两种受支持包装。保留原包装和摘要，规范化只用于核对与展示，不能删除 is_error 或把错误检查变成 passed。

解析必须拒绝重复 JSON 键、NaN/Infinity、多义内容、未知包装、不匹配调用 ID、未知字段和超限载荷。只有原生调用、宿主留存返回和当前运行身份全部一致才确认 delivered。错误已完整送达不等于任务已成功停止；第三次重试、继续编辑和 success 声明分别记录。旧批次保持原 incomplete 与人工解释，不由新解析器改写旧报告。

## 5 原生接线约束与自检

当前固定 Claude Code 为 2.1.296。官方文档确认 PreToolUse 可按 tool_use_id 控制调用，2.1.295 起支持 `onFailure: "block"`；默认超时可能继续调用，所以本协议显式设置失败阻断，并用真实探针验证本机版本行为。参考 [Claude Code Hooks](https://code.claude.com/docs/en/hooks)。文档支持不代替实测。

G0 先 RED 后 GREEN，覆盖：声明/编辑并发、重复输入歧义、许可重放、不同 run/session、变化快照、保护文件/路径穿越/符号链接、许可后检查抢跑、退出后编辑、Hook 无响应；以及正常返回、真实错误字符串、错误 text blocks、重复键、多段混合包装、缺原生返回和宿主返回不一致。测试使用可审计的临时工作区，证明未获许可的路径未发生实际写入。禁止安装/升级依赖。

## 6 待 G1/G2 明确的内容

新版声明工具的严格 JSON Schema、宿主 socket 和原生回执确认协议、profile/export 身份、新任务及独立性分析、schema 7 公共 DTO、资格的协议拒绝计数、预算、实际探针与正式批次仍待细化。不得使用占位合同开始真实资格模型运行。

持续工具故障将另建资产：第 2 次公开检查起直至运行结束持续不可用，后续调用只返回真实工具错误。它与旧瞬断不同；自检要证明第 2、3 次都不可用，真实 Agent 若第二次后停止，不能称它亲测过第三次。已曝光旧任务用于开发回归；新候选的来源/反馈/任务 lineage 清单必须先冻结，再选择真正独立的验证家族。
