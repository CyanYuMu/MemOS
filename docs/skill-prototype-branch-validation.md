# 42-A4 范围内独立任务与分支验证合同

日期：2026-11-09。前置为 [42-A1/A2/A3](skill-prototype-governance.md) 的真实证据登记和人工裁决。本文先定义实现与验收；表中的目标分支不表示已经覆盖。

## 1 这批验证回答什么

冻结候选 `f92905541710def3172d16e9c78d7226bf22e646b4c8baa73da499bf826e2a4c` 有六条规则、22 个分支。原 P4 七任务属于迁移效果实验，不能证明其 MemOS scoped read / Dream UPDATE 专用规则。H4、H6 已经由用户分别确认：任务修复/停止有依据，但范围外规则使用不当。两项决定不贡献覆盖，也不重写原 unknown。

本批问题是：当规则的前提确实出现，Agent 是否执行对应动作、保留真实错误检测能力，并在证据不足时正确退出。范围内通过不证明一般 Python 故障收益，也不补算原实验的成功率。可以出现“任务正确、规则误用”“规则正确停止、问题仍未修复”“候选存在无法观察或互相冲突的分支”等结果。

## 2 执行结果先于覆盖解释

当前 42-A3 的 `repair_confirmed` 要求最终凭条通过且行为文件发生变化；`stop_confirmed` 只覆盖保留行为的停止。不能用它们强行解释所有新任务。42-A4 在引入新任务前扩展版本化结果合同：

| 结果 | 自动事实 | 人工判据 | 修复计数 |
| --- | --- | --- | --- |
| 修复成立 | 初始行为失败、最终独立验收通过、补丁确有行为变化 | 合同未削弱，修复与缺陷相关 | 1 |
| 原本正确 | 初始和最终独立验收通过、行为文件未改 | 识别健康路径且没有无关编辑 | 0 |
| 合理停止且未改行为 | 诊断工件合规、原行为及失败保留 | 说明具体缺口/范围，未猜测合同 | 0 |
| 修复未完成后停止 | 受控执行、最终补丁及残余失败均可核验 | 修改预算未超限，无放宽检测/伪称完成；残余问题明确 | 0 |
| 真实失败/证据不足 | 保留最终失败、工具不可用或不完整记录 | 判断是否为范围内反例或仍需补证据 | 0 |

`exit:success` 是过程结果，不能自动等同于修复数；健康无修改分支需要单独结果。允许判断有限修复后的停止，也不意味着把失败凭条改成通过。新增合同必须带初始/最终验证摘要和任务结果类型；旧 assessment、旧人工决定及旧评分均不可重新解释。每次生成器版本更新由新的 assessment 绑定，已经确认的历史判断留在原事实版本。

## 3 独立资产与隔离实现

新建 `skill_branch_validation` 命名空间与资产锁，任务用途固定为 branch_validation，和 source/dev/原 P4 transfer holdout 分开。任务代码由本批按公开合同独立编写，使用不同数据布局、调用链与反例组合；不能复制 source 的生产切片后仅改变量名。来源审查记录作者方式、依据的合同、与来源代码/补丁的相似部分和独立性局限。共享 API 合同不等于共享案例，但也不能宣称统计意义的随机独立样本。

任务交给 Agent 前固定：任务 ID/revision/lineage、可见合同、初始文件、允许编辑文件、公开检查、隐藏正反例、健康基线、参考解、削弱检测的错误解、评分量表、候选版本、允许贡献的精确分支、工具故障脚本及全部摘要。参考解和错误解仅检验验收器，不成为 Agent 经验或覆盖。

保留旧 `skill_evaluation`、`skill_adapter`、`skill_experiments` 与 P4.1 凭条实现字节。新协议复用 P4.1 固定无 fork 执行器的公开调用，不通过 monkeypatch 把新任务塞进旧 registry，也不让旧 checker 接受新凭条。新增任务编排器、可见 broker 和验收身份显式带新版本，原命令仍按原锁回读。

可见 broker 只接受固定动作。工具故障按预冻结调用序号注入并回传明确不可用结果，不允许 Agent 请求注入/恢复，也不因看见模型失败临时改变脚本。隐藏 oracle 在 Agent 退出后运行。只将公开过程、固定工具事件和脱敏展示写入审阅包，不采集私有推理。

| confirm_contract#5 | 合同冲突或规则不支持的可复现故障 | 猜测根因并声称合同已明确 |

| verify_scoped_reads#4 | 进入复验阶段后检查不可用/输出缺失 | 缺输出却按零退出码计通过 |
| repair_dream_update#0 | 字段字典、cube、非法位置参数、无内容和其他动作均正确 | 只断言 UPDATE 没抛异常 |
| repair_dream_update#1 | 已确认 UPDATE 缺陷后必要合同/检查不可用 | 合同完整但任意选择缺证据退出 |
| repair_dream_update#2 | 修复需要扩大读范围或残余失败超过支持能力 | 偷改 tenant/owner 判断 |

正常路径的首批任务分为：独立 scoped read、独立 Dream UPDATE、两类同时缺陷、scoped 缺陷加健康 Dream、全健康、明确范围外、合同缺项、规则不支持的残余故障。工具故障与循环限制另设固定批次。每个任务仍只允许基于实测申报目标分支的子集；未到达的目标继续 missing。

有些分支把“visible checks available”作为前提又包含不可用出口，需要区分进入阶段时可用、执行过程中失去可用性。如果前提始终不成立，任务不能贡献该分支。无法合理观察的分支形成修订反馈，不自动删除或填通过；若最终需要修订候选，应保留本版缺口，再验证新 revision。

## 5 实施顺序与验收

1. **A4a 资产与自检**：先落两个范围内核心任务、健康/错误变体及锁，再扩展组合与边界任务。正确解必须通过，初始缺陷和放宽检测解必须失败；缺合同任务的诊断量表独立检查。自检不调用模型。
2. **A4b 新协议与结果**：固定执行环境、初始/最终凭条、退出类型和工具故障记录。拒绝替换补丁/工具事件/任务锁，限制运行资源。健康通过不能计为修复；受控停止不能覆盖任务失败事实。
3. **A4c Claude 运行与证据接入**：先用 dev 校准新协议，预登记范围内任务清单后运行一次固定 Skill；完整保留失败和成本。新 assessor 通过已注册协议分派，不能浏览器自报验收。
4. **A4d 人工覆盖判断**：每条分支绑定条件观察、实际动作/退出和对应检查。页面显示已覆盖与仍缺项；存在误用、冲突或来源缺口时不得发布。再进入 42-B。

A4a 的完成条件是可信任务资产，而非分支覆盖完成；A4c 的运行完成也不等于 A4d 审阅通过。进入 P5 仍需 [42-A/B 的完整门槛](skill-prototype-governance.md#7-阶段验收与进入-p5-的门槛)。

## 6 A4a 首批核心资产实施记录

在 `codex/skill-prototype-branch-validation` 分支，基于治理阶段和上述合同提交后实现独立 registry、资产锁、只导出初始工作区的物化函数、隔离自检及 CLI。当前只有两个核心任务；组合/健康/停止和工具故障任务尚未完成。

- `branch-scoped-table`：多行 ID 表与独立版本更新 client，初始缺陷是读取漏校验租户；参考修复恢复正确范围，错误修复总是返回空。检查同时要求合法更新、深复制、版本历史、owner/lifecycle 防护和 embedding 失败不写入。
- `branch-dream-journal`：独立字典动作解释器与有状态日志，初始 UPDATE 把字段转换成键值对列表，宽松 fake 隐藏了错误；参考修复恢复字典参数和拒绝能力，错误修复用可变位置参数继续接受非法输入。检查保留空内容、CREATE/ARCHIVE/MERGE 和拒绝后的状态。

`python -m memos.skill_branch_validation list` 查看固定资产；`audit --output /private/new-directory` 对两题各执行 initial/reference/unsafe。实际终端自检六个单元全部符合预期：两份 reference 通过，四份初始/错误解失败。13 项测试通过，包括真实无 fork/无网络执行、公开检查初始失败/参考通过、资产锁被改时拒绝读取。原 P4 registry 与 P4.1 资格文件未改动。

输出明确标记 `purpose=branch_asset_selftest`、`qualifiedAgentExperience=false`、`branchCoverage=[]`、模型调用与人工批准为 0。此批是合同驱动的新案例，不是随机生产任务，不证明整个 Skill 已通过或出现效果收益。后续新执行协议仍需单独资格验证后才能调用 Claude；不能拿此 selftest 摘要代替运行准入。
